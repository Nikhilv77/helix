# AI/ML Architecture & Design release review

The AI/ML path uses the existing `/practice/architecture-design` page, question workspace, Prisma-backed blocks and attempts, owner-scoped API, assessment, history, and adaptive continuation. Canonical progress, submitted answers, and the shared design canvas live in the database. The canvas uses an owner-scoped block API with revision checks and keeps conflicting unsaved edits visible for the candidate to resolve; it does not use browser storage in Architecture practice. The shared UI still uses session storage for retry IDs and legacy inline assessment draft recovery. There is no forked AI/ML architecture engine. The two scenarios below passed automated schema, coherence, dimension-coverage, and public-answer-leak audits. Following the project owner's request to make the reviewed path available, both scenarios were approved in source and published to the verified development database on 2026-09-23.

Two additional cases are drafted in [`ai-ml-scenario-candidates.ts`](../src/features/practice/architecture-design/domain/ai-ml-scenario-candidates.ts): personalized feed ranking and document vision intake. They have `reviewStatus: "candidate"` and are not in the active catalogue or database publication payload. The project owner must review their prompts, evidence, answers, and rubrics before they can be approved and published.

| Scenario                              | Stage 1: requirements and scale                                                                                                                            | Stage 2: contracts and data                                                                                                                           | Stage 3: architecture and failure                                                                                                                       | Stage 4: quality and evolution                                                                                                                                                               |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Retrieval-augmented support assistant | Scope authorized, cited answers and abstention; size a 2,000-document/s change stream at three chunks per document against a five-minute freshness target. | Repair source, chunk, embedding, index, and citation identities; enforce tenant scope and deletion across live indexes, rebuilds, and caches.         | Separate bulk indexing from interactive retrieval and generation when a tenant import drives queue age to 12 minutes and provider p95 to eight seconds. | Reject an apparently more grounded candidate when citation correctness falls from 99.7% to 97.8% and p95 rises above the four-second target; design joint model/index rollback.              |
| Real-time fraud decision platform     | Define approve/challenge/review and a 120 ms p99 path at 40,000 peak decisions/s; reconcile 100 million daily attempts with 8,000 daily human reviews.     | Repair point-in-time feature joins, merchant authorization, missingness, event idempotency, delayed-label lineage, and reproducible decision records. | Isolate merchant bursts and a feature-store slowdown while preventing silent zero-valued features and unbounded review fallback.                        | Reject a candidate with an eight-point recall regression in a high-risk segment and 9,360 projected daily reviews against an 8,000-case capacity; define shadow, canary, and rollback gates. |

Each scenario has four linked questions, three progressive hints per question, a distinct evidence artifact at each stage, a private reference answer and rubric, and coverage of all 16 Architecture & Design dimensions. The stage formats use the same written, artifact-diagnosis, and production-decision controls as the existing domain. The numerical values are teaching fixtures, not claims about a real production system.

The full prompts, artifacts, hints, reference answers, rubrics, and failure cases are in [`ai-ml-scenarios.ts`](../src/features/practice/architecture-design/domain/ai-ml-scenarios.ts). The content review checked that authorization revocation is immediate even though index freshness is bounded, fraud training excludes features unavailable at decision time, and the rollout stop decisions match the supplied evidence.

3. A read through the real eligibility service returned `AVAILABLE`, two published AI/ML scenarios, and both expected scenario keys. The Architecture practice card therefore opens against the development database. Production publication still follows the protected production database workflow.

Both source approval and database publication gates now pass for the development environment. Backend and full-stack candidates continue to use their six role-specific scenarios.
